# 座舱 UI 改造复审：潜在 BUG 与三指手势

**审查范围**：`cc916005..75f9cabe`（三区座舱、半屏设置抽屉、自绘退出确认、Dock 第五键、仪表卡常驻），
以及 `CarPlayHostActivity` 里与这轮改造直接相关的三指下滑通路。

**结论**：改造的方向是对的，主结构没有致命问题；**七处是真 BUG**（其中一处会误触、一处会让画面停住、
一处让返回键短暂失效），其余是性能与一致性上的欠账。三指手势原来是 4 个布尔量塞在 `onHostTouch` 里，
本轮换成独立状态机并补了 10 条用例；手势的目标也从"老的全屏设置页"改到"首页 + 抽屉"。

---

## 已修

### 1. 三指抬起后仍有事件被当成孤立触点发给 CarPlay（`CarPlayHostActivity.onHostTouch`）

原实现判定通过后把两个标志清零，于是**同一串触摸里剩下的 `MOVE` 会被转发给手机**，而手机从没见过
对应这一串的 `DOWN`。CarPlay 侧表现为一个凭空出现的触点。现在 `ThreeFingerSwipeDetector` 有一个
`DRAINING` 状态：触发之后一直吞到最后一根手指抬起。

### 2. 两根静止的手指 + 第三根手指随手一按 = 误开设置（同一函数）

原实现只要求"当前同时有 3 个触点"，不看它们怎么来的。手搭在屏幕上（两根手指停着），第三根手指
落下按到任何东西都会武装手势，然后一次轻微下滑就把设置页顶出来。现在加 **350ms 装填窗口**，从第一
根手指的 `DOWN` 算起，超时不算手势。

### 3. 快速一划如果最后一帧位移不够，手势失效（同一函数）

旧逻辑只在 `ACTION_MOVE` 里判距离。快划的最后一帧常常是 `ACTION_POINTER_UP`（抬指），位移刚好不够
阈值，这一划就白划了。现在抬指事件也参与判定。

### 4. 手势状态机可能卡在"武装中"（同一函数）

`ACTION_CANCEL` 在 3 指仍按下时，旧代码既不清理 `gestureSequenceActive` 也不清理 `gestureTracking`
（分支条件互斥），要等下一次 `ACTION_DOWN` 才自愈。窗口失焦、系统接管触摸时都会走到这里。
现在 `CANCEL`/`UP` 一律归零，并且 `onWindowFocusChanged(false)` 与 `onStop` 也会 `reset()`。

### 5. 三指下滑落到"第二套设置界面"（`openSettingsMenu`）

改造后首页的设置收进了半屏抽屉，但三指手势仍然 `showDiPlayHome("settings")` → 打开老的整页设置
（`Your drive, your way.` 那一版，另一套标题与排版）。等于这次改造声称"一个设置面"之后，又留了
第二个入口。现在手势 = 首页 + 抽屉（`EXTRA_OPEN_SETTINGS_DRAWER`），和齿轮、快捷卡同一个面。

### 6. 抽屉每次重绘都"重新滑入 + 跳回顶部"（`SettingsDrawerView.open` / `DiPlayActivity.render`）

`open(animate: Boolean = false)` 这条路**从来没有被调用过**：`cockpitRoot` 里写的是
`openSettingsDrawer()`，用的是默认 `animate = true`，而 `open()` 里又无条件 `scrollTo(0, 0)`。
注释写的是"comes back without its slide"，代码不是。后果：在抽屉下半部分改任何一项（比如"右舵"、
"分辨率"）都会触发 `render()`，抽屉重新滑入并回到"外观"一节。现在重绘走
`restoreSettingsDrawer(offset)`：不滑入、不重置，`scrollOffset()` 先取出、放回。

### 7. 快速"开→关→开"会把抽屉留成 GONE，而 Activity 仍认为它开着

`ViewPropertyAnimator` 的 `withEndAction` 在动画被取消时也会执行，而 `close()` 的 end action 是
`visibility = GONE`。两次点击间隔小于 180ms 时，新开的抽屉会被上一段的收尾动作关掉，此后点齿轮没
反应、返回键第一下"吃掉"。现在 `open()`/`close()` 先 `cancel()` 正在跑的动画（含 end action），再
按目标状态重新起。

### 8. 抽屉关闭动画的 180ms 内，返回键被吞（同上）

`isOpen()` 看的是 `visibility == VISIBLE`，动画期间一直是 true，于是第一次返回只触发"再关一次"，
第二次才生效。现在返回键看 Activity 的 `drawerOpen`，`closeSettingsDrawer()` 也做成幂等。

### 9. 首页 hero 的连接状态是冻结的（`DiPlayActivity.refreshStatus`）

`pageState()` 把结果缓存到下一次 `render()` 为止，而 `refreshStatus()` 每秒调它一次。首次 tick 之后
**每一秒画的都是同一份快照**：连接在页面可见期间结束，胶囊仍写"已连接"。现在阶段现算
（`sessionPhase(hasSession(), active)`，两个布尔量，很便宜），只有昂贵的 readiness 探测继续按一次
重绘一次缓存。

### 10. 跟随时间的日夜皮肤到点不切换（`refreshStatus`）

`AUTO_CAR` 靠配置变更回调，`AUTO_TIME` 什么都没有：18:00 到了，画面要等下一次重绘才变。现在 tick 里
用 `resolvePalette` 现算一次并与当前调色板做**身份比较**（调色板是常量对象，不是值比较，不会因为
"皮肤本身就是暗色"而反复重绘）。

### 11. 首页重绘会先造一整页再扔掉（`render`）

`render()` 无条件构造 `ScrollView` + 头部 + `content`，最后 `page == "home"` 时用座舱替换掉。
26MB 空闲的车机上每秒/每次交互都多建十几个 View。现在 home 分支在建页之前返回。

### 12. 点已经选中的无线段仍会写存储、重建页面、并进入 setup 模式（`QuickWidgetsView`）

`onModeSwitch` 对当前段照样触发 `applyWirelessLink`，而它默认 `setupPending = (mode == MANUAL)`：
也就是说**点"内置车机热点"这个已经选中的段，会把页面推进"先保存热点名称和密码"的状态**。现在只有
真正换段才触发。

### 13. Dock 五个按钮读屏全空，图标语义反了（`SlimDockView`）

`contentDescription = null` 写死；音频用"显示器"图标、设置用"信息 i"图标。现在每个按钮有
`contentDescription`，并新增 `ic_dp_settings`（齿轮）、`ic_dp_speaker`（喇叭）两张矢量图。

### 14. 从设置页回来，新 Surface 没有请求关键帧（`CarPlayHostActivity.attachSurface`）

三指下滑会离开 CarPlay 画面，窗口被隐藏、`TextureView` 的 surface 被销毁、解码器按设计留下继续跑。
回来时 `setSurface` 只是换输出面（API ≥ M 走 `setOutputSurface`），**没有任何地方向手机要 IDR**；
CarPlay 画面静止时不发 IDR，于是画面停在离开前那一帧。现在 `attachSurface` 时如果流已经在跑，就
在 `airPlayCommandExecutor` 上补一条 `forceKeyFrame`。

## 记录、未改（附理由）

| 项 | 位置 | 说明 | 为什么不在这轮改 |
|---|---|---|---|
| 抽屉首次打开一次性构建全部设置 | `buildSettingsDrawer` | 含 14 格频道网格、`ClusterMapPresentation.findDisplay`、实验区；冷开抽屉会有一次明显卡顿 | 要改成懒构建得把 section 的 lambda 生命周期重排，风险高于收益，建议下一轮单独做 |
| 右舵只镜像了 Dock | `cockpitRoot` | `loadRightHandDrive` 把 Dock 放右边，但抽屉固定从右侧滑出（方向盘在右时应从左侧） | 是设计取舍，需要确认产品意图，不是 bug 修复 |
| `settings` 整页现在没有生产入口 | `render` 的 `"settings"` 分支 | 只有外部 intent（`DiPlayActivity` 是 exported）与测试会走 | 删页会牵动 `SettingsPagesUiTest` 约 15 条断言，应当单独一个提交 |
| `MENU_*` / `MAX_SETTINGS_MENU_WIDTH_PX` / `NO_VIDEO_BACKGROUND` | `CarPlayHostActivity` 伴生对象 | 只有 `MENU_SECONDARY`/`MENU_ACCENT` 还有一处日志视图在用，其余是死常量 | 纯清理 |
| `CarPlayTouchMapper` 用 pointer index 当 contact id | `shared/.../CarPlayTouchMapper.kt` | 多指抬起时 index 前移，等于把 1 号触点"瞬移"到 0 号；CarPlay 只吃 2 个触点，所以影响有限 | 与这轮 UI 无关，改动面在 shared，建议单独修 |
| R8 后 `R.string.home_page` 之类新串的本地化 | `values-zh-rCN` | 已补中文"首页"，其余语言缺省英文 | 现有语言只有中英 |
| 抽屉遮罩 `0x55` 在白底皮肤上偏淡 | `SettingsDrawerView.SCRIM` | 可读性可以，但不是强对比 | 视觉项，等实车截图再定 |
