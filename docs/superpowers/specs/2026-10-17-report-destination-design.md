## 〇、v2 错在哪（先认账）

1. **方案一把"猜挂载点"放在了第一层。** 猜 `<vol>/DiPlay/` 就是在猜 U 盘叫什么、挂在哪——猜不中就没有然后。正确顺序是**先问系统要"第二个卷上的本包目录"**（`getExternalFilesDirs()` 的第 2 项起），那是系统给的，不需要知道卷名；猜的名字只配做第二层。
2. **方案二把"同一网络"当成了不需要解释的默认前提。** 它确实是硬前提，但可以把它压缩成"扫一次码"：二维码里直接写 Wi-Fi 凭据，手机相机扫一下就自动连上，不用输密码——前提是 App 能读到热点名和密码，而 E01 上这条链是通的（`getWifiApConfiguration` 权威可信，已有 `CarHotspotCredentials` 在用）。

## 一、方案一：能不能成，先看一件事

### 1.1 卷名不重要，挂载点才重要，而挂载点不用猜

| 需要的东西 | 谁给 | 是否要"知道名字" |
|---|---|---|
| 可写的落点 | `getExternalFilesDirs(null)` 的第 2 项及以后 | **不要**。系统直接返回 `<卷>/Android/data/<pkg>/files` |
| 插盘时的真实路径 | `ACTION_MEDIA_MOUNTED` 广播的 `data`（`file:///storage/usbotg/usbotg-sda1`） | **不要**。路径随广播进来 |
| 卷的显示名 | `File.getName()` / `StorageVolume` 反射 | 只用于弹窗上写"U 盘 (usbotg-sda1)"，纯装饰 |

三条里任一条成立就够了，第一条最常见。

### 1.2 硬边界（必须写在前面，不能靠文案遮）

> 如果 E01 把 U 盘挂成**厂商私有挂载**（不在 `getExternalFilesDirs` 里、不发 `MEDIA_MOUNTED`、FUSE 又不给普通 app 写本包目录），那**在没有 root 的前提下，方案一不可能成功**。

这不是"再想想办法"能绕过的：C 位被系统拿走了。v2 的错误是把这件事藏在了"三层都试"后面，等于让用户去点一个注定失败的按钮。

**所以方案一的存在条件由 App 自己判**：

```
computed once when the diagnostics card is drawn:
  writableVolumes = 枚举() 中 mkdir 探测通过的那些
  if (writableVolumes.isEmpty())  → 不显示「存到 U 盘」按钮，只显示「用手机取」
  else                            → 显示按钮，并在按钮下方小字写 "U 盘 (usbotg-sda1)"
```

按钮出现本身就是探测结果。用户永远不会点到一个"理论上不可能成功"的按钮。

### 1.3 写入顺序（改了）

1. **b. `<卷>/Android/data/<pkg>/files/DiPlay/`** —— 系统给的、契约保证可写的位置。先写它。
2. **a. `<卷>/DiPlay/`** —— 只有 b 之外的落点才算"用户好找"；写成功则优先报告这个。
3. **c. `Download/DiPlay/`** —— 本机，保证成功，拔盘不丢。

判定：a 或 b 成功 → 「已存入 U 盘 + 真实路径」；只有 c → 不报成功，直接转方案二。

### 1.4 失败也要有信息（无 adb 的取证）

失败弹窗底部加一行 12sp 小字，用户截图就是证据：

```
发现 2 个卷 · usbotg-sda1 可写(包目录) · 根目录 EACCES
```

这行字替代了原来的 adb 清单：**用户不需要懂，截图发回来就够定位**。

## 二、方案二：需要同网，但可以只是一个"扫码"

### 2.1 先回答"是不是要同一个网络"

是。手机必须能路由到车机。但这一步不需要用户理解：

- 车机开热点（已有 `wakeCarHotspotInBackground`，热点名/密码可读）；
- 屏幕出**两张码，编号 ①②**：

```
① 扫码连车机 Wi-Fi          ② 连上后扫这个下载
[ WIFI:T:WPA;S:AndroidAP;P:xxxx;; ]   [ http://192.168.43.1:8080/<token> ]
   手机相机直接连，不用输密码            手机浏览器直接下 zip
```

① 是标准 Wi-Fi 二维码（`WIFI:` 格式）。iOS 11+ 相机原生识别；Android 侧不统一——Google 系多半认，国产 ROM 未必，别当成必然。所以②旁边保留一条"连不上就手输"的降级：用大字显示 SSID 与密码（是否愿意当众暴露热点密码，见 §七.3）。

② 的 IP 取当前 `ap0`/`wlan0` 的 site-local 地址（E01 热点通常是 192.168.43.1），端口随机，token 一次性、5 分钟有效、只服务一个 GET、只读一个 zip（报告 + 最近 2 份日志）。

### 2.2 为什么不做"连上就自动弹下载页"（captive portal）

想过，**在无 root 下做不到**：手机连上后的联网探测走 DNS，而 DNS 由系统 tethering 起的 dnsmasq 掌管，App 改不了它的解析。所以"自动弹登录页"这条路直接划掉，别写进方案。

替代就是两张码，或者②的 URL 顺手做成短一点、让用户能在浏览器里敲。

### 2.3 成本

`HttpOnce`（ServerSocket + 单次 GET + 超时）约 90 行 · IP/端口/token 约 30 行 · **QR 编码器自写**（byte 模式，版本 1–10，EC=M）约 250 行 + 3 组已知向量单测 · 两张码的 UI 约 60 行。

## 三、两条路的关系（改了主次）

- **方案二升为主路径**：它不依赖文件系统、不依赖 OEM 挂载策略，只依赖"车机能开热点"，而这一条已经验证过。
- **方案一降为"顺手"**：能写就省一步，不能写就自动消失（§1.2），不承诺、不欺骗。
- 两条共用同一份 `buildDiagnosticReport()` 字节，互不依赖。

---

## 四、可选第三路：不同网也能取（只在"车机常联网"时值得做）

车机联网 → 报告上传到已有 Supabase 桶 → 屏幕显示 6 位取件码 → 用户在手机/电脑打开一个固定网页输入取件码下载。

- 优点：不需要同网、不需要 U 盘、不需要热点。
- 代价：需要服务端一条只写策略 + 一个静态页；且车机没网时完全不工作——而"没网"恰恰是最常见的故障场景。
- 结论：**不做进首发**。若后续官方包要开埋点（见 `2026-10-17-telemetry-design.md`），这条可以顺带落地。

## 五、落地顺序

1. **探测与回显**（半天）：卷枚举 + 可写探测（`mkdir` 试写）+ errno 透出 + `uri == null` 分支。**这一步没有任何新功能，但让后面所有判断有依据，也让用户第一次看到真实原因。**
2. **方案二**（主路径）：QR + Wi-Fi 码 + one-shot HTTP。先上它，因为它是唯一不依赖 OEM 的那条。
3. **方案一**（顺手）：按 §1.2 的条件显示按钮，三层写，失败转二。
4. **收口**：删掉 `choose_save_location`（`DiPlayActivity.kt:732`）和 `CreateDocument` 这条路（`:201-203`），一个出口一个按钮。

## 六、验收（不用 adb，只看屏幕）

| 场景 | 期望 |
|---|---|
| 车机热点开着 → 点「用手机取」 | 两张码出现；① 扫完手机自动连上（不弹密码框） |
| ② 扫码 | 5 秒内下到 zip；5 分钟后同一链接 404 |
| 手机已连着车机热点 | 直接扫 ② 即可，① 可忽略 |
| 热点没开 | 按钮先引导开热点；开不了则只留方案一 |
| 系统不给可写卷 | 「存到 U 盘」按钮不出现（不出现，而不是点了失败） |
| 有可写卷 → 点保存 | 弹窗路径在电脑上粘贴可打开；截图里的诊断行与事实一致 |
| 写入中拔盘 | 不崩、不假成功 |
