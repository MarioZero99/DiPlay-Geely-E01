# DiPlay Geely E01 — v0.4.1-geely

星瑞 E01 车机的 CarPlay 端口。对应车机是 ECARX E01 / MediaTek MT6735 / GKUI 19，
系统 **Android 5.1（API 22）**。

底子还是 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**，这一版没再对上游。
直接覆盖安装就行，之前存的设置和热点都还在。

---

## 从 0.4.0 到现在，改了什么

**设置页又变回一页了。** 上一版把设置拆成四个入口，得挨个点进去找自己要的那一项。
这一版十三项全摆在一页上，无线那三步的 `1 · 2 · 3` 编号留着。车机屏幕宽，
卡片按**两两一行**排，一屏能看到的东西差不多多了一倍。

**无线**

- 车机上压根没有能跑这条路的东西时，页面会直说**这台车机不支持**，
  而不是列一串「还差什么」——那些缺的东西，司机一个也补不上。
- **热点没开成，不会再顺手把你的车机 Wi-Fi 关掉。** 以前是重试的时候无条件先关 Wi-Fi，
  结果固件拒绝开热点，你自己的 Wi-Fi（连着 Wi-Fi 调试的话也一起）就没了，而且不回来。
  现在只有「放掉 Wi-Fi 真有可能成功」的时候才放；放完还是没成，会给你放回去。
- 一次连接被后面那次顶掉之后，不再留着自己的发现应答器在那儿——一个进程就一个。
- 走这条路失败时，原因以前进不了诊断报告，现在进去了。

**有线**

- USB 那头不读了，接收队列以前是没有上限的（这车可用内存经常只剩 26–33 MB）。
  现在到 1 MiB 就当作对端断开处理，和收到 RST 走同一条路。
- 手机上还在弹「是否允许」的那几秒，不再把这条通路上的写失败当成故障。

**另外**

- 进了热点设置不保存也能退出来；被拒的连接那张卡会重新算，不再记着当时那个答案；
  无线模式选过之后，永远留着一个改回去的入口。
- 把比亚迪的 HUD、电池、充电那部分从这个移植里去掉了——E01 上没有对应的硬件。

## 在什么车机上做的

**吉利星瑞 E01**（ECARX E01 / MT6735 / GKUI 19 / Android 5.1 / API 22）。

| | |
|---|---|
| 车机软件版本 | **5068**（出厂那批是 5066） |
| 系统内部版本 | `SWFS11G0706H5181.00600` |

想自己看一眼：车机 **设置 → 关于智能平台 → 版本信息**。

版本号和上面不一样，不代表不能用；但下面那段风险提示落到你的车上**可能和这台不一样**，
自己判断。

> 这一版有的部分上过车，有的没有。上面写的是代码里改了什么；没验过的那些，
> 车上通不通得你自己试。

## ⚠️ 先说清楚：无线会动车机蓝牙的底层

**这段看完再决定装不装。**

无线 CarPlay 借的是车机自己那套厂商蓝牙。为了把 CarPlay 要的数据通道接上，
DiPlay 会**动车机正在跑的那个蓝牙底层进程**：

- **不写 `/system`。** 系统分区不动，**车机重启就自己回去了**，你不用做任何事。
- **应用里没有「撤销」按钮。** 想马上还回去，重启车机。
- 这个改动**会一直留到车机重启为止**——不是「只用无线的时候才发生」。
  你只是打开 DiPlay，什么都不做，它也会发生。

**风险，自己掂量：**

- 车机自己的蓝牙（**打电话、放蓝牙音乐**）和改过的进程搭不搭得上，**没在车上试过**。
  原厂进程被换掉了，这两件事有可能不正常。
- 真出问题，一般的办法是**重启车机**。
- 这是**非官方改动**。吉利 / ECARX **不给任何支持**，由此带来的问题**不在保修范围**，
  也可能影响车机后面的官方 OTA 升级。

**不想担这个风险，就别装。有线 CarPlay 什么都不用动。**
