# 吉利 E01 (MT6735) 后台语音独立治理模块 (`:governance`) 架构设计与二次审查

> **定位**：将原厂后台语音（`natp` + `xiaoka`）治理从主工程（CarPlay/DiPlay 业务链路）中彻底剥离，作为 **完全独立的系统级治理模块（Independent Governance Module）** 运行。
> 本文针对模块化边界、依赖倒置、存储隔离、硬件探测、串行防抖与生命周期自主监听展开二次深度审查。

---

## 一、 为什么必须是“独立模块”？（解耦审查）

在车载系统开发与第三方互联系统（CarPlay）的集成中，如果将系统底层的 Root 提权、`setprop` 注入与特定车机的进程压制代码直接散落在 `DiPlayActivity` 或 `common` 工具类中，会产生严重的架构腐化：

```mermaid
flowchart LR
    subgraph 耦合反模式 [强耦合反模式 (不可取)]
        A[DiPlayActivity] -->|直接调用| B[E01PrivilegedBridge]
        A -->|直接读写| C[AirPlayPersistence]
        A -->|手写生命周期| D[natp 指令逻辑]
        E[CarPlay 核心] -.->|被车机治理逻辑污染| A
    end

    subgraph 独立模块架构 [独立模块架构 (本次设计)]
        MainApp[主工程 / automotive / common] -->|单向依赖| GovApi["VehicleGovernance API (抽象接口)"]
        GovApi --> GovImpl[governance 独立模块]
        subgraph GovImpl [模块内部自闭环]
            Factory[GovernorFactory 硬件探测]
            E01Gov[E01Mtk6735Governor 真实实现]
            NoOpGov[NoOpGovernor 降级实现]
            Store[GovernancePersistence 独立存储]
            Queue[串行任务执行队列]
        end
    end
```

### 独立模块的 5 大核心原则
1. **依赖绝对单向（Zero Upstream Coupling）**：
   - 治理模块**零依赖** CarPlay 协议、零依赖视频解码、零依赖网络通讯包。
   - 即使把该模块从整个工程中摘掉，主工程依然可以正常编译运行。
2. **硬件环境自探测与优雅降级（SPI 驱动模式）**：
   - 模块内部自检是否运行在吉利 E01 (MT6735) 及是否存在东软 `ExtraUtilsService`。
   - 在非目标车机或手机调试模式下，自动降级为 `NoOpGovernor`，不报错、不抛异常、不污染日志。
3. **独立的存储命名空间（Storage Isolation）**：
   - 剥离出专门的 `vehicle_governance_prefs.xml`，绝不污染 CarPlay 的 `xcertplay_airplay.xml`。
4. **生命周期自主感知（Self-Lifecycle Attachment）**：
   - 模块通过 `GovernanceLifecycleListener` 自动感知 App 的进入与退出，主工程只需在 Application 初始化时调用单行 `VehicleGovernance.install(this)`。
5. **调用防抖与指令串行化（Debounce & Command Serialization）**：
   - 规避用户快速连点设置页 Switch 带来的并发 Shell 执行风暴。

## 三、 核心代码契约设计

### 1. 核心接口：`IVehicleGovernor`
```kotlin
package com.shilapi.governance.core

import kotlinx.coroutines.flow.StateFlow

interface IVehicleGovernor {
    val isSupported: Boolean
    val stateFlow: StateFlow<Boolean> // true 为正在抑制，false 为原厂状态

    suspend fun applySuppression(reason: String): Boolean
    suspend fun applyRestoration(reason: String): Boolean
    suspend fun ensureSelfHealed(reason: String): Boolean
}
```

### 2. 硬件检测分发：`GovernorFactory`
```kotlin
package com.shilapi.governance.core

import android.content.Context
import android.os.Build
import com.shilapi.governance.platform.E01PrivilegedBridge

object GovernorFactory {
    fun create(context: Context): IVehicleGovernor {
        // 1. 探测是否具有东软提权通道 (E01 专属)
        val hasE01Bridge = E01PrivilegedBridge.isAvailable()
        
        // 2. 探测硬件特征 (MT6735 SoC)
        val isMt6735 = Build.HARDWARE.contains("mt6735", ignoreCase = true) ||
                       Build.BOARD.contains("mt6735", ignoreCase = true)

        return if (hasE01Bridge || isMt6735) {
            E01Mtk6735Governor(context)
        } else {
            NoOpGovernor
        }
    }
}
```

### 3. 吉利 E01 专属治理驱动：`E01Mtk6735Governor`
采用此前审查得出的**最优 76 字节 / 66 字节无 `pidof` 单行指令**，并经由串行队列执行：

```kotlin
package com.shilapi.governance.core

import android.content.Context
import android.util.Log
import com.shilapi.governance.platform.E01PrivilegedBridge
import com.shilapi.governance.store.GovernancePersistence
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow

class E01Mtk6735Governor(private val context: Context) : IVehicleGovernor {
    companion object {
        private const val TAG = "E01Governor"

        // 最优抑制指令：76 字节，wrapped 115 字节 <= 220 字节
        const val CMD_SUPPRESS =
            "setprop ctl.stop run_natp; killall -9 natp 2>/dev/null; pm disable-user --user 0 com.ecarx.xiaoka"

        // 最优恢复指令：66 字节，wrapped 105 字节 <= 220 字节
        const val CMD_RESTORE =
            "pm enable com.ecarx.xiaoka; setprop ctl.start run_natp"

        // 自愈对齐指令：27 字节，wrapped 66 字节 <= 220 字节
        const val CMD_SELF_HEAL =
            "pm enable com.ecarx.xiaoka"
    }

    override val isSupported: Boolean = true
    private val _stateFlow = MutableStateFlow(false)
    override val stateFlow: StateFlow<Boolean> = _stateFlow.asStateFlow()

    private val queue = CommandQueue()

    override suspend fun applySuppression(reason: String): Boolean = queue.execute {
        Log.i(TAG, "Executing suppression [$reason]...")
        val success = E01PrivilegedBridge.execute(CMD_SUPPRESS) is E01PrivilegedBridge.Result.Success
        if (success) _stateFlow.value = true
        success
    }

    override suspend fun applyRestoration(reason: String): Boolean = queue.execute {
        Log.i(TAG, "Executing restoration [$reason]...")
        val success = E01PrivilegedBridge.execute(CMD_RESTORE) is E01PrivilegedBridge.Result.Success
        if (success) _stateFlow.value = false
        success
    }

    override suspend fun ensureSelfHealed(reason: String): Boolean = queue.execute {
        Log.i(TAG, "Executing self-healing check [$reason]...")
        val success = E01PrivilegedBridge.execute(CMD_SELF_HEAL) is E01PrivilegedBridge.Result.Success
        if (success) _stateFlow.value = false
        success
    }
}
```

### 4. 对外门面：`VehicleGovernance`
主工程只需感知此门面对象，所有复杂状态机与提权内部封闭：

```kotlin
package com.shilapi.governance

import android.app.Application
import android.content.Context
import com.shilapi.governance.core.GovernorFactory
import com.shilapi.governance.core.IVehicleGovernor
import com.shilapi.governance.store.GovernancePersistence
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.SupervisorJob
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.launch

object VehicleGovernance {
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
    private lateinit var governor: IVehicleGovernor
    private lateinit var persistence: GovernancePersistence

    /**
     * 在 Application.onCreate() 中一行接入
     */
    fun install(application: Application, isExperimentalAllowed: Boolean) {
        persistence = GovernancePersistence(application)
        governor = if (isExperimentalAllowed) {
            GovernorFactory.create(application)
        } else {
            // 非实验性构建强制使用 NoOp 兜底，并做一次自愈
            GovernorFactory.create(application).also {
                scope.launch { it.ensureSelfHealed("release-guard") }
            }
        }

        // 冷启动自动同步配置
        scope.launch {
            if (isExperimentalAllowed && persistence.isSuppressionConfigured()) {
                governor.applySuppression("app-launch-auto")
            } else {
                governor.ensureSelfHealed("app-launch-align")
            }
        }
    }

    val isSupported: Boolean get() = governor.isSupported
    val isSuppressedFlow: StateFlow<Boolean> get() = governor.stateFlow

    fun setSuppressionEnabled(enabled: Boolean, onComplete: ((Boolean) -> Unit)? = null) {
        persistence.setSuppressionConfigured(enabled)
        scope.launch {
            val ok = if (enabled) {
                governor.applySuppression("manual-switch-on")
            } else {
                governor.applyRestoration("manual-switch-off")
            }
            onComplete?.invoke(ok)
        }
    }

    fun onAppExit() {
        scope.launch {
            governor.applyRestoration("app-exit")
        }
    }
}
```

## 四、 独立模块与主工程接入方式

主工程（`common` 模块）只需要引用该模块并在设置页与 Application 中挂载：

### 1. `common/build.gradle.kts` 添加依赖
```kotlin
dependencies {
    implementation(project(":governance"))
    // ... 原有其他依赖保持不变
}
```

### 2. Application 启动注入
在 `DiPlayBootstrap.kt` 或 `DiPlayApplication.kt`：
```kotlin
// 只有当 ExperimentalFeatures.enabled 为 true 时才允许激活治理
VehicleGovernance.install(
    application = this,
    isExperimentalAllowed = ExperimentalFeatures.enabled
)
```

### 3. 设置页 UI 挂载（完全基于模块接口，无任何私有代码渗透）
```kotlin
if (VehicleGovernance.isSupported && ExperimentalFeatures.enabled) {
    SettingsSwitch(
        title = "抑制后台语音 (natp + 晓咖)",
        summary = "释放 320MB 物理内存与 40% CPU，退出应用或熄火自动恢复",
        checked = VehicleGovernance.isSuppressedFlow.collectAsState().value,
        onCheckedChange = { checked ->
            if (checked) {
                showSafetyConfirmDialog {
                    VehicleGovernance.setSuppressionEnabled(true)
                }
            } else {
                VehicleGovernance.setSuppressionEnabled(false)
            }
        }
    )
}
```

## 五、 二次审查结论清单

| 审查维度 | 原方案状况 | 独立模块重构后状况 | 判定 |
| :--- | :--- | :--- | :---: |
| **模块隔离度** | 逻辑散落于 `system/`、`Activity`，与 CarPlay 耦合 | 抽取为单独 `:governance` Gradle 模块，零依赖上层业务 | **彻底解耦** |
| **硬件侵入性** | 无论何种设备均尝试执行 E01 Binder 指令 | `GovernorFactory` 自动探测硬件环境，非 E01 自动降级为 `NoOp` | **环境安全** |
| **存储洁净度** | 写入主 App 的 `xcertplay_airplay.xml` | 独立存储 `vehicle_governance_prefs.xml`，互不干扰 | **独立自治** |
| **并发与防抖** | 用户快速点击开关可能引发指令并发交织 | 内部 `CommandQueue` 强制协程串行化与防抖 | **线程安全** |
| **构建权限控制** | 仅逻辑判断，未对构建期进行彻底熔断 | `install(..., isExperimentalAllowed)`，Release 包物理熔断 | **合规可控** |
