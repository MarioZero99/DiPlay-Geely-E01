# DiPlay Geely E01 — v0.4.5-geely

星瑞 E01 车机的 CarPlay 接收端。对应车机是 ECARX E01 / MediaTek MT6735 / GKUI 19，
系统 **Android 5.1（API 22）**。versionCode **45**，包名 `com.shihab.diplay`。

底子还是 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**，这一版未再对齐上游。
签名与上一版完全一致，**直接覆盖安装即可**，之前保存的分辨率、音频缓冲、方向盘按键和 Wi-Fi 凭证均完整保留。

这一版的核心优化：**「同一 Wi-Fi」无线模式首连速度大幅提升（IPv6 优先秒连 + 地址族内存常驻记忆）**，以及**车机音频缓冲调优建议**。

---

## 一、「同一 Wi-Fi」IPv6 优先秒连与记忆（个人热点 / 同 LAN）

针对 iPhone 个人热点或局域网 Wi-Fi 下，车机 IPv4 ARP 解析偶尔延迟（`empty-arp`）导致首连白等 5000ms 超时的问题进行了底层改进：

- **默认 IPv6 Link-Local 优先秒连**：在「同一 Wi-Fi」模式下，默认优先选用 IPv6 地址发起广播与握手，绕过 IPv4 ARP 解析开销，实车连接从 5 秒级缩短至毫秒级瞬间接入。
- **协议握手候选优化**：在 0x4301 StartSession 端点描述中优先推荐 IPv6 地址，同时保持看门狗失败自动回退 IPv4 的完整弹性。
- **地址族判断常驻进程内存**：单次成功建立的地址族（IPv6 / IPv4）以及重试过程中的回退决策在应用运行期间常驻内存，退出后台或界面重建时不丢失记忆，免去每次重连重新摸索的等待；同时按热点模式（车机 AP / 同一 Wi-Fi）严格隔离，杀进程后自动归零。
- **线程安全与模式隔离**：重构 `WirelessAddressFamilyGuess` 状态机，增加并发锁消除后台看门狗与主线程的竞态，并在「同一 Wi-Fi」与「车机热点（MANUAL）」之间建立独立缓存隔离，杜绝模式切换后的地址族污染。

## 二、音频播放配置建议（针对吉利星瑞 E01 车机）

- **强烈建议将「音乐缓冲」恢复为默认 500ms**：
  - 在吉利 E01（Android 5.1 / MT6735）平台上，`AudioTrack.write()` 为底层同步阻塞调用。
  - 若手动设为 1000ms，缓冲区总容量为 1200ms，起播门限 1000ms 导致安全冗余仅剩 200ms（约 16%）。实测解码线程单次阻塞（`maxWriteMs`）最高飙升至 637ms，Wi-Fi 偶发抖动极易引发 MTK ALSA 驱动 DMA 欠载回绕（出现卡顿并偶尔重复播放前几句歌词），且 1 秒以上延迟会破坏 iOS AirPlay 的 NTP 时钟同步。
  - 恢复为默认 500ms 时，容量 700ms 具备充足安全冗余（占比近 30%），`maxWriteMs` 保持在 0~2ms，既消除断音卡顿与语句重复，又保障声画精准同步。
