# DiPlay Geely E01 — v4.0-geely-rc

吉利星瑞 E01（ECARX E01 / MediaTek MT6735 / GKUI 19，**Android 5.1 / API 22**）的 CarPlay 车机端口。

基于 `programmerguohuajing/DiPlay-Legacy-Android` **v0.2.7**。本版没有重新核对上游。
覆盖安装，原来的设置和配对记录还在。

这一版是从 0.3.5 一路累上来的，改的地方不少。下面按你在车上会看到的分。

---

## 连接页重做

整页按车机那块 24:9 的屏重排：左边是状态、四步进度条和一个主按钮，右边是 USB 和握手记录，
顶上一栏放连接方式和设置。**不用滚动**——以前那列是竖着排的，1920×720 上比屏幕还高。

**进度条说的是真话。** 以前剩下所有状态都被当成最后一步，数据通路还在开，页面已经显示到
最后一格了。现在这张对应表只有一份，有线无线各一条梯子；控制器以后新增状态，必须同时放进
两条梯子，否则编译不过。

选 iPhone、以及连接被拒的原因，都搬到页面上，不再是一个个要点掉的弹窗。

**插上 USB 设备不再自己开始连接。** 以前插上 iPhone 线就直接进 CarPlay。现在只有按连接
按钮才会连。

有线连不上时，主按钮上直接写该怎么办——口、线、插头方向、供电——不再一律「重新连接」。

## 有线

- 拔线当场报「iPhone 被拔掉了」，不再等读超时才反应。
- 一直「正在等待 iPhone」时，会把**总线是空的**（口、线、插头方向）和**插着的东西不是手机**
  分开说。
- CarPlay 自己会让手机离开总线再回来，**这不算掉线**——不然连着三次好连接就会被判成线松。
- 等 CarPlay 配置那一步加了十秒兜底，不再可能永远卡着。
- **iPhone 17 Pro Max 掉线是供电。** 上车确认了：它要的电比车机 USB 口给得多，电一塌会话
  就断，然后重连。不是线的问题，也不是 App 的问题。这一版没改它，也没让它更糟。要绕开就接
  一个带供电的 USB Hub。

## 无线

- 7000 端口被占着（上次没退干净的进程，或者别的 App）不再让整次连接失败，会自动换一个空闲
  端口。
- 起不来的时候会写出是哪个端口、哪个地址、哪个协议族，不再只丢一句 `BindException`。

## 诊断

这一版把「出了问题看不到」这条路补了一大批：

- 传输、媒体、网络的每一行都进会话记录。以前只进 logcat，而这台车机上没有 adb——那些行是
  唯一能说明为什么连不上的东西。
- **log 还没建起来时写的行会先攒着**，建起来立刻补上。一次运行最开头那几秒恰恰是说明问题的
  那几秒，以前正好被丢掉。
- **启动就崩也会被写进会话记录。** 以前崩在第一次会话之前，哪都没写——而那正是最想看的一种。
- 报告会自己说**丢了多少行**（队列满、写失败、磁盘满），不再跟「这次运行很干净」长得一样。
- **有字节预算，但优先保住有用的行。** 以前是四段几乎一样的「没找到」，预算全花在重复上，
  真正解释问题的那一行反而进不去。
- 报告**能拿出来了**：会写到 `Downloads/DiPlay`、所有外置存储，以及车机用的 USB 挂载点。

## 其他

- **车机热点的名字和密码从车机自己读**，装完不用手填。热点按实际用的密码推断安全模式——以前
  会把车机的 WPA2 热点当成开放网络，设置页和热点管理器两边都会拒绝它。
- 语言选择只留这个移植真正翻译了的两种。
