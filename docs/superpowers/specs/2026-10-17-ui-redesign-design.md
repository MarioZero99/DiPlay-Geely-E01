# DiPlay 车机互联 UI & 交互全局重构设计规范 (Design Spec)

- **版本**: 1.0.0
- **日期**: 2026-10-17
- **目标平台**: 吉利 E01 车机（Android 4.4 / 5.1+，1920×720 @ 160dpi 超宽屏）
- **默认皮肤**: **极氪白（ZEEKR_WHITE · 先锋纯白 + 极氪高能橙点缀）**
- **可选皮肤**: 魅族白（FLYME_WHITE · 灵动纯白 + 魅族科技蓝点缀）
- **夜间模式**: 按照系统时间 **18:00 至次日 06:00** 自动切换为防眩光暗黑模式

---

## 一、 重构背景与目标

### 1.1 现有痛点
1. **视线与布局错配**：1920×720 物理比例为 8:3（超宽、极扁）。原界面采用顶部大标题 + 纵向大卡片滚动，大量挤占原本只有 450dp 的纵向高度，驾驶员在行车中上下翻页不便。
2. **色彩缺乏原厂级高级感**：原界面基于单调的冷深蓝（#0C111B / #151E2C）搭配高对比实线描边，缺乏现代主流新能源车机（如 ZEEKR OS、FlymeAuto）明亮通透的纯白天幕质感。
3. **技术参数干扰主驾驶流程**：
   - 待机界面展示无意义的静态投屏帧率监控（CarPlay 启动后即独占全屏，待机显示帧率纯属冗余）；
   - 将打包内置的底层 MFi 证书和复杂的跳板调试暴露在外，干扰普通车主核心连接心智；
   - 无线模式展示了车机不跑的虚构模式，未收敛至真机跑通的两种拓扑。

### 1.2 重构目标
1. **1920×720 黄金宽屏布局**：左侧常驻 Slim Dock（82dp，近主驾位，盲操一触即达）+ 中左部 58% 核心 Hero 互联舞台 + 右侧 42% 快捷功能卡片。
2. **默认极氪白高奢色彩体系（支持极氪白 / 魅族蓝双皮肤切换）**：默认采用极氪白（纯白浮雕卡片 + 先锋高能橙点缀），亦可在设置中随时切换为魅族蓝皮肤。
3. **智能夜间模式联动**：按系统时间自动在 **18:00 至次日 06:00** 切换至防眩光夜间暗黑模式，白昼自动恢复为极氪白（或选定的魅族蓝）。
4. **功能降噪与信息重组**：彻底剔除待机伪帧率与 MFi 证书干扰，无线模式精准收敛为「车机热点」与「同一网络」二选一。

## 二、 平台与架构约束

| 维度 | 规格与硬性约束 |
|---|---|
| **目标硬件** | 吉利博越/缤越 E01 原厂车机（MTK 平台，亿咖通定制固件） |
| **屏幕规格** | 物理分辨率 1920 × 720 px @ 160dpi（Density = 1.0，即 1px = 1dp，有效可用区 1920×720 dp） |
| **系统兼容** | Android 4.4 (API 19) / Android 5.1 (API 22) 至 Android 8.1+ |
| **UI 实现机制** | **纯 Kotlin 代码构建原生 View（View DSL）**，禁止引入 Jetpack Compose（避免低版本 DEX 膨胀与启动掉帧） |
| **渲染性能** | **零全屏实时高斯模糊**（低配车机 GPU 承受不住），所有微光与浮雕质感均采用原生 `GradientDrawable` 复合层与轻量阴影模拟，确保 60 FPS 满帧 |

### 3.2 夜间模式自动切换调度机制
1. **时间判据**：
   ```kotlin
   fun isNightTime(calendar: Calendar = Calendar.getInstance()): Boolean {
       val hour = calendar.get(Calendar.HOUR_OF_DAY)
       // 18:00 - 23:59 或 00:00 - 05:59 判为夜间
       return hour >= 18 || hour < 6
   }
   ```
2. **主题解析器 (`resolveEffectiveTheme`)**：
   - 若用户配置为 `AppThemeMode.AUTO`（系统默认）：
     - 夜间（18:00-06:00）自动返回 `DARK_MODE`；
     - 白昼（06:00-18:00）返回用户偏好皮肤（默认 `ZEEKR_WHITE`，若选过魅族白则返回 `FLYME_WHITE`）。
   - 若用户手动强制指定某皮肤：直接采用指定皮肤，不随时间切换。
3. **时钟感应监听**：
   - 注册系统 `Intent.ACTION_TIME_TICK`（系统每分钟回调），跨越 06:00 或 18:00 阈值时触发 Activity 平滑重绘（`render()`）。
   - Activity `onResume()` 时主动检查一次时间，从后台返回即刻校准。

### 4.1 左侧 Slim Dock（常驻近主驾驶位）
* **宽度**：固定 82dp，铺满纵向 720px。
* **按键排布**：
  * 顶部：
    * `主页` 图标：常驻选中态，点击回到连接主页。
    * `音频路由` 快捷图标：点击直接弹出小型音频通道快捷拨块。
  * 底部：
    * `设置与维护` 图标：点击平滑唤起右侧半屏设置抽屉。
    * `退出` 按钮：平滑销毁 Activity。

### 4.2 Hero 核心互联主舞台（占宽 58%）
* **定位**：主驾视线黄金区域，驾驶员上车只需确认一件事——手机是否连上、按键进入投屏。
* **组成要素**：
  1. **状态标识**：圆润胶囊状态条，展示呼吸绿光点 + `CARPLAY 无线就绪` 字样。
  2. **设备元数据**：展示当前蓝牙配对握手成功的设备全称（如 `已配对：张三的 iPhone`）。若未发现手机，显示 `等待手机靠近...` 并展示引导短语。
  3. **数字化能量环图腾**：极简细线双环旋转微动效，取代原来突兀的假手机插画，强化科技感与原厂感。
  4. **主控双按键组**：
     * **主按键**：`进入 CARPLAY 投屏`（高 52dp，全圆角 10dp，根据主题采用深黑曜石大键或高能色，带触控微缩放 0.98x 反馈）。
     * **次按键**：`USB 有线连接`（高 52dp，浅色浮雕边框，点击触发 USB 投屏通道）。

### 4.3 右侧快捷卡片网格（占宽 42%）
严格收敛至日常用车必需的高频项：
* **模块 1：无线互联模式二选一拨盘**：
  * 彻底收敛为真实可用的两个选项，提供平滑分段拨块：
    1. `车机热点（推荐）`：车机开启 5.8GHz AP，底层通过 GOC SPP 交换热点口令与 SSID（最稳定原生方案）；
    2. `同一网络（同网）`：车机 Wi-Fi 与 iPhone 连入同一个随身 Wi-Fi 或外网。
* **模块 2：原车音效输出路由**：
  * 展示 `E01 原车原生混音通道 (Channel 0)`，并标注支持导航媒体立体声混音。点击可快速展开通道选择面板。
* **模块 3：系统维护抽屉触发条**：
  * 单独一行轻量卡片：`高级设置与极客诊断抽屉`，点击平滑从右侧滑入设置面板。

### 4.4 高级设置与维护抽屉（Half-screen Slide Drawer）
取代原全屏沉重滚动的 Settings 页，以右侧 50% 宽度的浮动抽屉展示，背景带轻微暗化蒙层：
1. **座舱外观**：
   * 主题模式单选：`极氪白（默认）`、`魅族蓝`、`夜间暗黑`、`自动（18:00-06:00 夜间）`。
2. **显示与投屏策略**：
   * 分辨率偏好（1920×720 最佳宽屏 / 原生比例）；
   * 边缘裁切（Margin Override）。
3. **音频高级设置**：
   * 音频通道 0~6 切换（默认 Channel 0）；
   * 导航音频流类型切换（STREAM_VOICE_CALL / STREAM_NOTIFICATION）。
4. **底层固件与极客维护**：
   * GOC 蓝牙跳板状态与重新劫持；
   * 诊断日志一键导出（导出为文本供排障）；
   * 软件版本与开源声明。
5. **彻底剔除项**：
   * **MFi 证书导入/配置项**：包内自带，严格不对用户暴露；
   * **伪待机帧率/码率监控**：彻底剔除。

## 五、 数据结构与持久化改动

### 5.1 主题枚举与持久化 (`AirPlayPersistence.kt`)
```kotlin
enum class AppSkin(val key: String) {
    ZEEKR_WHITE("zeekr_white"),
    FLYME_WHITE("flyme_white"),
    NIGHT_DARK("night_dark")
}

enum class ThemeSchedule(val key: String) {
    AUTO_TIME("auto_time"), // 18:00 - 06:00 为夜间
    MANUAL("manual")
}
```
* 持久化字段：
  * `app_skin`: 存储选定的白昼皮肤（默认 `ZEEKR_WHITE`）；
  * `theme_schedule`: 存储主题调度策略（默认 `AUTO_TIME`）。

### 5.2 无线网络模式持久化同步
* 保持现有 `AirPlayPersistence.loadHotspotMode()`，界面上仅向车主呈现 `MANUAL`（车机热点）与 `EXISTING_WIFI`（同一网络）。

## 六、 动效与微交互规范

1. **触控微缩放（Press Micro-scale）**：
   * 所有卡片和按钮在 `ACTION_DOWN` 时平滑缩小至 `0.98f`，在 `ACTION_UP` 或 `ACTION_CANCEL` 时以 150ms 弹性回弹恢复 `1.0f`。
2. **呼吸指示灯（Alive Breathing Glow）**：
   * 就绪状态光点采用 2.5 秒周期的 Alpha 渐变动效（`0.6f` 至 `1.0f` 往复），避免刺眼闪烁。
3. **分段拨盘滑动（Pill Switch Transition）**：
   * 在「车机热点」与「同一网络」切换时，选中的白色滑块使用属性动画横向平移，提升机械精致感。
4. **抽屉滑入滑出（Drawer Translation）**：
   * 设置面板从屏幕右侧 `translationX = width` 平滑滑入至 `translationX = 0`，耗时 220ms，插值器采用 DecelerateInterpolator。

## 七、 实施自检清单（Spec Self-Review）

1. **无占位符（Placeholder Scan）**：文档中无任何 `TBD`、`TODO` 或模糊描述，各色值、尺寸、时段与组件行为均有确定数值。
2. **内部一致性（Internal Consistency）**：
   - 默认皮肤全篇明确为 `ZEEKR_WHITE`（极氪白）；
   - 屏幕尺寸全篇严格对应 1920×720；
   - 两种无线模式与 E01 代码中的 `MANUAL` / `EXISTING_WIFI` 完全同源；
   - 夜间时间段全篇统一为 18:00 至次日 06:00。
3. **范围可控（Scope Check）**：重构聚焦于表现层 UI 与交互组件重写，不破坏底层的 CarPlay 会话状态机（`CarPlayController`）与 GOC 蓝牙通讯协议。
4. **消除歧义（Ambiguity Check）**：
   - 明确指出无需引入 Compose，使用纯 Kotlin 原生 View；
   - 明确指出 MFi 证书由 APK assets 自动加载，彻底移出 UI。
